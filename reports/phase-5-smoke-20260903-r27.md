The [verbatim diagnostic trace](phase-5-metrics/two-tier-smoke-v3-20260903-4d6cf2f-r27/browser-fireside-initial.json.diagnostics.jsonl)
now identifies the denied target: a no-filter `invitedUsers` collection query
under the current user's license. It returns `REMOVE`, code 7, with
`path interpolation requires a string, integer, or path`. The request's hashed
parent matches the corresponding [official trace](phase-5-metrics/two-tier-smoke-v3-20260903-4d6cf2f-r27/browser-official-initial.json.diagnostics.jsonl),
which delivers the self-invite document and CURRENT. The earlier startup query
against the placeholder license is denied by both; that denial is not the defect.
Target IDs are session-local and must be correlated with request shapes, not
compared as global IDs across navigations.

The rule's leading `!exists(.../invitedUsers/$(invitedUserLicense))` contains an
unbound child wildcard during list authorization. Fireside raises an error
before the OR can evaluate a provable grant based on the concrete parent owner.
This is a different mechanism from r25's missing field-filter constraints for
`presentations.createdBy == uid`. That owner query is present in r27's requests
and independently passes the existing native/browser regression fixture; the
newly rejected invited-users query is an earlier application dependency.
R26 did not preserve enough evidence to prove this cause then. No retrospective
claim that r26 passed or had a fully established cause is made.
