## Failure attribution and next oracle boundary

The [verbatim diagnostic ledger](phase-5-metrics/two-tier-smoke-v3-20260903-710bfb7-r25/browser-fireside-initial.json.diagnostics.jsonl)
records the presentation-query error twice, at `10:57:23.275Z` and
`10:57:23.281Z`. At timeout, document and router remained `/home/recent`; the
startup spinner count was zero. The
[exact runner error](phase-5-metrics/two-tier-smoke-v3-20260903-710bfb7-r25/logs/browser-fireside-initial.log)
is `page.waitForSelector: Timeout 180000ms exceeded`, waiting for
`a[href^="/presentation/"]`. Navigation-cancelled Firestore long polls remain
the existing non-gating `net::ERR_ABORTED` class. No login-routing change is justified.

Read-only source inspection identifies a concrete query-authorization gap:

- Twodart's `ByMeTab.tsx` queries presentations with `createdBy == uid`,
  `updatedAt` descending, limit 12. Its rules' creator check reads
  `resource.data.createdBy`.
- Fireside `grpc-front/src/listen.rs::authorize_target` builds query/List
  evaluation with `current: None`. The unary query path does the same.
- `rules_query_from_structured` passes limit, offset and orderBy, but no filter
  constraints. The evaluator therefore has no resource on which to resolve
  `data`; its fallback produces the exact observed error text.

This is strong static attribution, not a captured reproduction of the exact
failing wire exchange. A follow-up must freeze official-emulator (and relevant
cloud) query-rule implication behavior before implementation, including positive
and negative owner-filter queries, empty result sets and Listen behavior.
Passing current rows through document checks, bypassing rules, or weakening the
query is not an acceptable substitute. No rules implementation was changed here.
