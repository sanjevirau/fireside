# WebChannel v8 oracle captures

These fixtures were generated by the pinned vanilla `firebase@12.18.0`
browser client through `fireside capture-proxy`. Each target/case directory
contains the redacted raw exchange sequence, a decoded view of query/form
fields and length-prefixed frames, and checksums for both JSON artifacts.

The official Java v1.22.0 captures were recorded on 2026-08-31 with Google
Chrome 151 on macOS against jar SHA-256
`9b6498b7f62714d67f48f59b3818883cd682dbcd46b9f59511de81c97bb5166c`.
They establish these Java-specific observations:

| Area | Observed Java v1.22.0 behavior |
| --- | --- |
| Handshake | `VER=8`, `CVER=22`, `X-HTTP-Session-Id=gsessionid`; folded `headers` form field; `count=1`, `ofs=0`; response `c` array carries SID, wire version 8, server version 12, and 30,000 ms keepalive. |
| Long poll | Backchannels use `RID=rpc`, `CI=1`, `AID`; each response closes after its available arrays. |
| Streaming | Backchannels use `CI=0`; document/current arrays and a later `noop` arrived as separate upstream body chunks in the captured Listen case. |
| Write forward ack | Streaming observed `[1,2,7]`; long polling observed `[0,1,7]` while no backchannel was open, followed by delivery on the reopened backchannel. |
| Retry/replay | The injected first backchannel loss produced a successful retry with `t=2`, `AID=0`, and consecutive replayed array IDs 1 through 5. |
| UTF-16 | CJK/emoji/mixed frames declared 468 or 783 UTF-16 units while occupying 501 or 816 UTF-8 bytes. Both `CI=1` and `CI=0` are captured. |
| Terminate | SDK teardown sends a POST with `TYPE=terminate`, SID, and RID. |
| Unknown SID | Java returned HTTP 400 with an empty body. This is a Java deviation candidate; Fireside will follow the production cloud capture if cloud returns the client-matched `Unknown SID` text. |
| Concurrent forward advertisement | Java did not return `X-Client-Wire-Protocol` in these HTTP/1.1 browser captures. Cloud remains authoritative for the production advertisement. |
| Overlapping Write requests | In both variants, two forward maps were sent before either write response and both carried the same last-acknowledged token `MA==`; Java accepted both and returned distinct next tokens `MQ==` and `Mg==`. |
| Inequality queries | A numeric `<= 2` range excluded null, NaN, and missing fields while returning numeric 0 and 1. The multiple-range query returned the two matching documents. Invalid document-key ordering and equality combinations returned `INVALID_ARGUMENT` with stable client-visible diagnostics. |

The production captures used the same pinned browser bundle and tiny synthetic
collection in the allowlisted `fireside-conformance` project. Application
Default Credentials were supplied through the SDK's credential-provider
interface, then redacted from the folded `headers` form value before the
fixture entered capture state. No cloud project configuration was changed.

| Area | Observed production Cloud Firestore behavior |
| --- | --- |
| Handshake | The request matches the Java `VER=8`, `CVER=22`, `X-HTTP-Session-Id=gsessionid`, `count=1`, `ofs=0` shape. The `c` array reported wire version 8, server version 14, and a 30,000 ms keepalive. |
| Session header | The handshake response returned `X-HTTP-Session-Id`; later requests copied that value into the `gsessionid` query parameter. |
| Concurrent forwards | The handshake response returned `X-Client-Wire-Protocol: h2` when the capture proxy negotiated HTTP/2 to the oracle. |
| Long poll / streaming | Forced long polling used `CI=1`; streaming used `CI=0`. Both used `RID=rpc`, `AID`, `TYPE=xmlhttp`, and the negotiated SID. |
| Write forward ack | The closed long-poll backchannel produced `[0,1,7]`. The streaming case produced `[1,1,7]`; the last-array field is timing-dependent and the invariant is the leading backchannel-presence flag plus outstanding-byte count. |
| Retry/replay | The injected loss reopened the backchannel with `t=2`, `AID=0`, and replayed consecutive array IDs 1 through 6 after handshake ID 0. |
| UTF-16 | Captured CJK/emoji frames declared 787 or 1,321 UTF-16 units while occupying 820 or 1,354 UTF-8 bytes. Both `CI=1` and `CI=0` are present. |
| Terminate | `TYPE=terminate` was an empty-body POST and returned HTTP 200; preserving its zero content length avoids an intermediary-generated HTTP 411. |
| Unknown SID | Cloud returned HTTP 400 with its generic HTML error body containing the literal `Unknown SID`; the checked-in raw fixture preserves the exact redacted bytes. |
| Overlapping Write requests | In both variants, two forward maps were sent before either write response and reused the same opaque last-acknowledged token. Cloud accepted both and advanced the returned token independently for each response. |
| Inequality queries | The numeric range and both document-key validation errors agree with Java. The multiple-range query itself returned `FAILED_PRECONDITION` with an index-creation diagnostic because the tiny capture project deliberately has no matching composite index; Java's successful result is therefore the permissive-emulator oracle for default mode. |

The proxy records the browser's original `Accept-Encoding` header but asks the
oracle for identity encoding. This capture-only normalization makes frames in
still-open streaming responses independently decodable; it is not evidence
that Cloud Firestore disables compression for ordinary clients.

The exact pinned source revisions were also read before implementation. The
Firebase Firestore browser adapter supplies `gsessionid`, encoded initial
headers, and the long-poll/proxy-detection options. The Closure transport uses
JavaScript string indices for frame lengths, promotes concurrent forward
requests after an `h2`/`spdy`/`quic` advertisement, copies the returned HTTP
session header into subsequent queries, and recognizes an unknown session only
when `Unknown SID` occurs after offset zero in an HTTP 400 response. These are
structural source confirmations; values that can vary remain locked by the
captured Java and cloud artifacts instead.

Dynamic SID, RID, nonce, timestamp, resume-token, stream-token, Origin, and
Date values are observations in the raw fixture, not constants for Fireside.
The replay tests assert structural invariants and use the decoded contract.
The supplementary `write-overlap` case was added after the first real Fireside
browser run exposed a stale-token rejection. It is an oracle fixture for the
already-frozen overlapping-forward-channel gate, not an expansion or weakening
of that gate.
